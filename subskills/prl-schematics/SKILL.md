# PRL scientific schematics

Create an original diagram that explains the supplied science at final publication size. Read [schematic design](../../references/prl-schematics.md) for source-backed composition choices, arrow semantics, geometry, color roles and examples. The [100-paper source index](../../references/schematic-sources.json) supports targeted source lookup; read relevant entries when a precedent matters, not all 100 by default.

For quantum circuits, optical trains, particle interactions, spin/lattice structures, continuum insets or state sequences, also use [cross-field design](../../references/crossfield-visual-design.md). Its 50 additional recent PRL papers provide 14 composition patterns. Call `../../scripts/select_crossfield_references.py --pattern PATTERN` for relevant source-bound observations, then turn the selected rule into concrete geometry and connection constraints in the image-model prompt. These visual-development references are separate from the frozen writing corpus.

1. Identify the entities, spatial constraints, directed relations and operations the reader must understand. Use the user's supplied science; resolve a missing arrow meaning or boundary condition when it changes the diagram. For a simple request, plan internally and proceed.
2. Choose physical geometry, apparatus plus detail, feedback loop, process sequence, interaction diagram or a mixed schematic/data composition. Fig. 1 does not automatically require a flowchart. Use [ordinary figure design](../../references/figure-design.md) for quantitative panels.
3. Select and call `../../scripts/prl_palette.py` unless colors were specified. Keep an entity's color across panels; distinguish categorical identity from numerical fields. Record the palette and object mapping with the source.
4. **Generate the PNG with the host's built-in image model first.** Use the native image-generation tool (for example `image_gen` in Codex), applying an available image-generation skill. Describe the science, hierarchy, spatial composition, selected colors and exact short labels. Inspect the actual image, then use targeted image edits to repair scientific or aesthetic defects. Favor deliberate spacing, clear visual hierarchy and refined scientific illustration over uniform boxes. A host without image generation needs an explicit alternative choice; do not silently replace this route with Python drawings or a paid API.
5. **Reconstruct the settled PNG as a genuinely editable `.pptx`.** Follow [PNG → editable PowerPoint](../../references/schematic-image-pptx.md): inspect the image, describe its objects and relations in a scene JSON, then use `../../scripts/schematic_to_pptx.py` or another available native-shape exporter. Text, nodes, arrows and key scientific geometry must be separate editable objects. A full-slide PNG is a reference image, not an editable reconstruction. Preserve composition, proportions, color roles and arrow directions; identify any intentionally retained raster components.
6. Render the PPTX with an available Office/LibreOffice engine and compare its actual rendered slide with the source PNG at final size. Repair clipped text, altered connections, shape distortion and degraded visual balance. If no renderer is available, report the structural checks separately from the unperformed visual check. Write a concise separate caption defining symbols and schematic/data status.

Default deliverables are **the model-generated PNG and an editable PPTX**, plus the caption and reconstruction source. Target 600 dpi at the intended physical size; record the generator's actual pixels and effective dpi. Metadata or upsampling does not create native detail. A 600 dpi rendering of native PPTX objects is a separate export, not the original generated PNG. Export PDF/SVG/EPS only when requested. Use Times New Roman for English/digits and SimSun for Chinese in native text; inspect generated lettering, whose exact fonts are not guaranteed. Do not install fonts. Keep essential labels close to their subjects; put explanations in the caption. Pure schematic panels normally have no numerical axes.

When the user explicitly wants code-drawn schematics, use `../../scripts/prl_schematic.py` and the six examples in `../../scripts/render_schematics.py`. This is an optional path, not the visual default. Quantitative panels still come from actual data and plotting code; the image model must not invent curves or measurements. Do not copy distinctive source artwork. Keep detailed review records separate from the figure and normal delivery prose.

Resolve linked scripts and references to their canonical targets before following relative resources. Pure schematics use entity/relation descriptions; the data-table figure contract is needed only for actual quantitative panels.
