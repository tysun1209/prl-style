# 从模型 PNG 到可编辑 PPT

默认先让当前 agent 的内置绘图模型完成视觉设计，再参照定稿重建 PowerPoint。模型负责构图与美感，PPT 原生对象负责后续修改。用户明确要求代码绘制时才使用原有 Matplotlib 路线。

## 生成：先定科学内容，再定视觉

从用户材料提炼对象、边界、方向、操作顺序与需要保留的短标签，调用配色库取得实际色值。提示词说明：论文插图用途、最终阅读宽度、主次关系、留白、视觉视角、颜色对应、确切文字和不能改变的科学关系。精致感来自比例、清晰的几何、曲线、字形与留白；不要自动加标题横幅、长注释、装饰图标或整齐但无信息的方框阵列。

可从下面的提示结构开始，按内容删改，不强制使用固定版式：

> 生成白底科学示意图，用于论文 Fig. 1。解释以下模型／方法：〔用户内容〕。主视觉是〔对象与作用〕，用〔整体与局部／状态序列／反馈关系〕组织。配色为〔已调用色卡的颜色与对象映射〕。箭头分别表示〔明确的起点、终点和含义〕。只保留标签〔准确文字〕，英文采用 Times New Roman 风格，中文采用宋体风格。最终宽度〔毫米〕，文字清晰、留白均衡、曲线流畅、线条精细。输出可用的最高原生分辨率 PNG，保持科学关系和几何一致。

查看生成图，而不是只检查提示词。核对箭头端点、重复对象、几何比例、文字拼写与占位。需要修改时用原图进行定向编辑；保留已经正确的部分。图像模型生成的字体与精确色值不保证完全一致，PPT 重建时用原生文字与指定颜色落实。

数据面板由真实数据绘制，和示意区分开生成后再排版。不要让图像模型补造曲线、误差棒、实验照片或模拟证据。纯概念示例在图注说明。

## 重建：把像素中的含义恢复成对象

PNG 没有可恢复的原始图层，不能可靠地“一键转成完全可编辑 PPT”。agent 需要看图、识别对象、建立对应关系，再调用导出工具。

1. 保留定稿 PNG；以相同宽高比建立 PPT 画布。
2. 按实际视觉边界划分对象：科学主体、容器与边界、箭头、轨迹、文字、放大引线、局部视图。为对象命名并按语义分组，便于在 PowerPoint 的选择窗格中修改。
3. 圆与盒子使用原生形状；复杂轮廓和曲线用可编辑自由曲线；箭头用连接线／路径的端点箭头，记录方向与含义；文字用真正的文本框。线与标签分开，字体与颜色可直接改。
4. 以生成 PNG 的布局为参照，保持主体比例、间距、颜色身份和曲线走向。必要的科学修正要明确说明。不要在转换阶段退回另一套机械模板。
5. 照片、复杂材质、体渲染可作为单独位图对象保留，列出哪些部分不能编辑内部结构。主要科学几何与所有标签仍要尽量重建；不要通过大量像素小方块制造“可编辑”的假象。
6. 第一页放重建图；第二页单独保留原始 PNG 并命名为视觉参照。完整 PNG 不铺在第一页底下冒充可编辑内容。

## 本包的导出器

依赖 `python-pptx`（已列入根目录 requirements）。读取[完整示例 scene](../assets/examples/model-first-schematic/fig1.scene.json)了解对象结构。它是 agent 看图之后写出的重建描述，导出器本身不做视觉识别。

```bash
python scripts/schematic_to_pptx.py assets/examples/model-first-schematic/fig1.scene.json --output figures/fig1.pptx
python scripts/schematic_to_pptx.py assets/examples/model-first-schematic/fig1.scene.json --output figures/fig1.pptx --office libreoffice
```

`--office` 指定现有 LibreOffice／soffice 可执行文件，实际打开 PPTX，并将第一页渲染为 `fig1.preview.png`（默认 600 dpi）；中间 PDF 位于临时目录，不作为默认交付格式。未提供此参数时只完成 PPTX 结构检查，不能宣称已验证打开后的视觉效果。

scene 的主要字段：

| 字段 | 含义 |
| --- | --- |
| `schema_version: 1` | 当前格式 |
| `width_mm`, `height_mm` | 最终物理尺寸，与源图宽高比一致 |
| `source_png.path`, `source_png.sha256` | 相对 scene 的源 PNG 路径与文件哈希 |
| `objects` | 从后往前的绘制顺序；每个对象有唯一 `id` 和 `kind` |
| `box: [x,y,w,h]` | 毫米坐标，左上角为原点，向右／向下为正 |
| `kind` | `rect`、`roundrect`、`ellipse`、`text`、`path`、`connector`、`group`、`raster` |
| `commands` | path 的 `M`、`L`、`C`（三次曲线）、`Z` 命令，使用同一毫米坐标 |
| `start`, `end` | 直线连接器端点；箭头由 `arrow_end`／`arrow_start` 指定 |
| `meaning`, `from`, `to` | 箭头含义与对象关系；不等同于 PowerPoint 的自动吸附 |
| `fill`, `stroke`, `line_pt`, `dash` | 填色、线色、磅值与虚线 |
| `text`, `font_pt`, `bold`, `align` | 真正的文本框内容与排版；默认英文 Times New Roman，东亚文字 SimSun |
| `objects`（group 内） | 分组对象，仍使用画布绝对坐标 |
| `path`, `raster_reason`（raster 内） | 保留位图的路径与原因 |

导出器检查源 PNG 哈希、画布比例、无效几何、重复 ID 和关系端点，保存后重新读取 PPTX 统计文本、原生对象和位图。它不自动识别遮挡、文字溢出或科学错误。连接器端点与路径可编辑，但移动节点后可能需要手动调整连线。

## 最终核对与分辨率

用可用的 PowerPoint／LibreOffice 打开或渲染 PPTX，检查实际文字换行、字体、箭头、图层和留白，再与源 PNG 并排查看。至少改一次文字、移动一个对象并保存重开，以确认内容不是扁平截图。没有渲染引擎时交代尚未完成的视觉检查，不用另一个绘图库的图冒充 PPT 截图。

600 dpi 是最终出版尺寸下的目标。178 mm 宽对应约 4205 像素。模型若只输出 1774 像素，则在该宽度下约为 253 dpi；改元数据或插值放大都不增加真实细节。保留模型原始 PNG 并记录这一事实。重建的原生 PPT 对象可以另行渲染为实际 600 dpi PNG；两份图需清楚区分。对保留的位图仍按其放置尺寸检查有效分辨率。

默认交付：**模型 PNG、可编辑 PPTX、图注**，同时保留 scene JSON。有渲染能力时附 PPT 预览。其他图像格式按需输出。若宿主没有内置图像工具，简短说明能力缺口，让用户选择可用绘图工具、提供定稿 PNG 或指定代码绘制；不要私自转用需要密钥或额外付费的接口。
